# AXIS Studio — ロボット・製造ラインシミュレーター

汎用6軸アームの軌道を3Dで設計・再生し、腕全体が指定領域に収まるか検証するローカルWebアプリです。React / TypeScript / Three.js / Viteで構成し、計算エンジンをブラウザーとCLIで共用しています。

**製造ラインシミュレーター**を追加しました。上部の「製造ライン」、または [http://127.0.0.1:5173/#line](http://127.0.0.1:5173/#line) で開きます。既存の6軸画面は `/` または `/#robot` です。

## 起動

Node.js 22.12以上（開発・検証環境: Node.js 24）を使います。

```sh
npm ci
npm run dev
```

[http://127.0.0.1:5173](http://127.0.0.1:5173) を開いてください。初回に標準の8秒の軌道を計算します。サーバーはローカルホストだけにバインドします。

```sh
npm run build
npm run preview
```

ビルド成果物は `dist/`。バックエンド・APIキー・外部計算サービスは不要です。Google Fontsが使えない場合はシステムフォントにフォールバックします。

## 操作

### 製造ライン / Control Lab

精密パーツの検品ラインを想定しています。4個までの搬入バッファから1個ずつ検品コンベアへ供給し、位置検出 → 減速停止 → 安定待ち → ロボット接近 → 検品 → 完了信号 → 退避 → 搬出、という工程を繰り返します。搬出コンベアには3個まで蓄積でき、下流の受入許可で搬送を制御します。

1. **再生**: ▶で開始、もう一度押すと一時停止。0.5〜10倍速、1スキャン進行、リセット、非常停止に対応しています。別タブに移ると再生を休止します。
2. **条件変更**: 搬送速度・加減速・供給間隔、停止命令後の開始待ち、検品時間、完了後の搬送待ちを変更します。変更すると再生を止め、次の開始・ステップで新しい設定を反映して先頭からやり直します。
3. **制御設定**: 「PLC・信号・監視」でスキャン周期、センサー遅延、保持式／パルス式完了信号、監視時間を調整できます。退避確認を外すと、検品完了直後の搬送による干渉も試せます。
4. **一括検証**: 現在の設定をWeb Workerで上限時間または生産完了まで高速実行します。直近5回の結果を実験ノートで比較し、設定復元・結果JSON保存ができます。アニメーション実行と同じエンジンです。
5. **故障注入**: 右側で位置センサーのON/OFF固着、完了信号遮断、搬出閉塞を切り替えます。リセット時には設定の「初期故障」に戻ります。検知された異常は保持し、リセットで再開します。
6. **ミッション**: 12個すべて良品で110秒以内の搬出を目指します。標準は供給間隔10秒で121.48秒、短縮プリセットは供給間隔7秒で85.29秒。生産数を変えた実験ではミッション達成にしません。
7. **保存**: ライン設定は専用localStorageに保存し、JSON読み込み・保存に対応します。6軸設定とは独立しています。設定JSONは下記の既存CLIでそのまま再現できます。一括検証の結果JSONも読み込み可能です。

「供給過多」「停止待ち不足」「退避の競合」「信号を見逃す」のプリセットで、原因・発生時刻・調整のヒントを確認できます。「供給過多」は3秒間隔で到着し、15.01秒に搬入バッファが満杯、18.01秒に次のワークが到着して `INPUT_OVERFLOW` で停止します。検品時間を1.20秒未満にすると、工程が流れてもNG品となり、成功判定されません。エラーを隠すための自動補正は行いません。

#### 製造ラインの判定と計算モデル

| 判定         | 意味                                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------------------- |
| `OK`         | 指定された生産数をすべて良品として最終出口まで搬出                                                   |
| `NG`         | 停止・安定待ち不足、作業位置超過、退避前搬送、信号タイムアウト、搬出詰まり、非常停止、またはNG品発生 |
| `UNVERIFIED` | 検証時間上限に到達して全数搬出を確認できない                                                         |

- **10 msの固定刻み**で物理状態を更新し、設定した周期でPLC入力読取り・制御を実行します。時間設定は次の計算刻みに切り上げます。同じ入力は再生速度や描画フレームレートによらず同じ結果になります。
- 検品コンベアは定加速度・定減速度、搬出は一定速度の蓄積搬送です。検品コンベア上は1ワーク、搬入・搬出は有限容量です。搬入は設定間隔どおりの定周期供給で、満杯でも供給元は待ちません。4個満杯は警告、空きがないまま次のワークが到着すると `INPUT_OVERFLOW` でNG停止します。容量超過のワークは追加せず、失敗を保持します。同じ10 ms刻みでは到着をPLCの引き取りより先に判定します。搬出端には機械式ストッパーを仮定します。
- 単位は **mm / 秒**。ワーク長120 mm、位置センサー1060 mm、検品可能な中心位置1000〜1260 mm、引渡し1800 mm、最終出口2600 mmです。センサーはワークが光軸を覆う間ONとなり、応答遅延後の値をPLCが読みます。
- ロボットは接近0.60秒、必要露光1.20秒、退避0.65秒、ワークの停止後安定時間0.20秒です。設定した検品時間が必要露光に届かないワークをNGにします。
- `PROCESS_DONE` は検品終了時に出力され、退避完了 `ROBOT_HOME` は別信号です。保持式は開始要求に対する応答としてPLC受信までON。パルス式はPLCスキャンの間に消える場合があります。
- 平均排出タクトは2個目以降の搬出間隔の平均、実績生産性は良品数÷立上げを含む経過時間、ロボット稼働率は接近・検品・退避時間の割合です。
- SVGは模式図で、アームは工程進捗に応じた2D補間です。干渉はロボット作業領域内での搬送から判定します。**6軸IK・3D形状衝突・力学・実PLC通信は未連携**です。非常停止・異常停止はモデルをその時点で凍結します。実機の制動や安全認証を再現するものではありません。
- 実行結果にはI/O履歴（直近1200サンプル）・イベント（最大4000件）・停止時の状態・設定が含まれます。途中の手動故障注入はイベントとして記録されます。現時点でCLI／設定復元が再現するのは初期設定からの実行であり、途中操作の自動再演ではありません。

```sh
# ブラウザーの設定JSON・一括検証結果JSONも指定可能
npm run simulate -- examples/line-standard.json output/line-standard
npm run simulate -- examples/line-optimized.json output/line-optimized

# 想定した故障。終了コード2
npm run simulate -- examples/line-overfeed.json output/line-overfeed
npm run simulate -- examples/line-rushed.json output/line-rushed
npm run simulate -- examples/line-race.json output/line-race
npm run simulate -- examples/line-pulse.json output/line-pulse
```

`config.json`, `result.json`, `events.csv` を生成します。終了コードは6軸と共通の **0=OK / 2=NG・UNVERIFIED / 1=入力エラー** です。

#### ラインの拡張

`src/core/line` はDOM・React・Three.jsに依存しません。設定／ライン定義、物理状態、PLC状態、スナップショットを分離し、描画とバッチ検証・CLIが同じ計算を使用します。

| ファイル                       | 責務                                                               |
| ------------------------------ | ------------------------------------------------------------------ |
| `src/core/line/types.ts`       | 設定、設備定義、ワーク、I/O、工程状態、異常、計算結果の契約        |
| `src/core/line/config.ts`      | ライン定義レジストリ、工程固有の物理条件、入力検証、実験プリセット |
| `src/core/line/engine.ts`      | 固定刻み時計、搬送・蓄積・センサー・ロボットの更新、監視、集計     |
| `src/core/line/controllers.ts` | PLC制御シーケンスとコントローラーレジストリ                        |
| `src/line.worker.ts`           | バッチ検証用Worker                                                 |
| `src/line/LineScene.tsx`       | 状態に基づくSVG描画・信号波形                                      |
| `src/line/LineStudio.tsx`      | 設定編集、再生、故障注入、検証結果比較、保存                       |

同じ検品工程の寸法・時間違いはライン定義から拡張できます。組み立て・複数ロボットなど異なる工程を追加する場合は、`lineId` とライン定義を追加し、物理更新・PLCシーケンス・描画を対応するモジュールに分けます。工程を自由配置するエディター、複数ライン間の接続、設備モデルの動的追加はまだ実装していません。

### 6軸ロボット / Motion Lab

1. **ロボット**: J1〜J6それぞれの長さ・直径・ローカル回転軸を設定します。「角度・可動範囲」を開くとIK探索の初期角度と関節制限も変更できます。
2. **軌道関数**: 手先位置 `x(t), y(t), z(t)`、全時間、時間刻みを入力します。必要なら姿勢の `roll(t), pitch(t), yaw(t)` も指定します。
3. **稼働領域**: 直方体のXYZ最小・最大、または球の中心と半径を指定します。
4. **軌道を計算**: 数値IKで関節角を探索し、各時刻とフレーム間の領域包含を検査します。計算はWeb Workerで実行し、中止できます。
5. **再生**: 再生・一時停止、スクラブ、速度変更、ループに対応。ドラッグでカメラ回転、ホイールでズーム、右ドラッグで平行移動できます。
6. **検証結果**: NG箇所の時刻をクリックすると、その姿勢に移動します。赤く表示されたリンクは現在の姿勢で領域をはみ出しています。
7. **保存**: 設定JSON、計算結果JSON（設定同梱）、関節角・誤差のCSVを出力できます。設定JSON・計算結果JSONのどちらも読み込み可能です。

有効な設定はブラウザーのlocalStorageに保存します。設定を変更すると古い結果は「未計算」扱いとなり、再計算までは再生・結果出力できません。初期設定へのリセットボタンもあります。

## 関数の書き方

位置・長さ・直径・領域は **mm**、時間 `t` は **秒**、画面・設定ファイルの角度と姿勢関数の出力は **度**です。数値エンジン内部の関節角とJSON結果の `frames[].angles` は **ラジアン**。CSVは度に変換します。

```text
x(t) = 520 + 90 * cos(2*pi*t/8)
y(t) = 140 * sin(2*pi*t/8)
z(t) = 400 + 60 * sin(4*pi*t/8)
```

演算子: `+ - * / % ^ **`、括弧、定数: `pi` / `PI` / `e`、変数: `t`。

関数: `sin cos tan asin acos atan atan2 sqrt abs exp log floor ceil min max pow`。`atan2`, `min`, `max`, `pow` は2引数、残りは1引数です。三角関数の引数はラジアンです。乗算記号 `*` は省略できません。`eval`やJavaScript実行は使用せず、専用パーサーで解析します。

姿勢は右手系、`R = Rz(yaw) × Ry(pitch) × Rx(roll)`。姿勢指定なしでは手先位置だけを解き、残りの自由度を領域制約などに使用します。

## ロボット・判定モデル

- 基準位置は `(0, 0, 0)`、Z-up。全関節は回転関節です。
- デフォルトのローカル回転軸は `Z, Y, Y, X, Y, X`。
- 各関節を回転してから、J1はローカルZ方向、J2〜J6はローカルX方向にリンク長だけ移動します。実機固有のDHパラメータやCAD形状ではありません。
- リンクは中心線分を半径 `diameter/2` の球で膨らませた**カプセル**。設定の長さは端点中心間の距離で、両端の丸みはさらに半径分張り出します。描画と判定で同じ寸法を使います。
- 端点球が凸な直方体・球の中に完全に収まれば、カプセル全体が内側にあります。手先だけ・中心線だけの判定は行いません。直方体は世界座標軸に平行です。
- 固定台座、軸表示、ラベル、TCPマーカーは領域判定の対象外です。J1の原点側の丸みを含めるため、通常は領域のZ下限を負にします。
- 初期角度はIKの探索開始値です。初期角度から最初の解までの導入動作は再生・検査に含めません。軌道の開始点 `t=0` の解から再生します。
- 再生は解の関節角を**線形補間**します。各時刻の端点判定に加え、フレーム間も中点と変位上界で再帰検査します。上界は `Σ |Δq_j| × その軸以降のリンク長合計`。境界への余裕が上界を超えた区間のみ安全と判定します。
- 浮動小数点の丸め許容は `1e-7 mm`。境界との接触は許容。ただし接触のまま移動するケースなど、深さ12または1024検査の上限内で安全を証明できなければ `UNVERIFIED` とし、OKにしません。

### 計算結果

| 値           | 意味                                                                               |
| ------------ | ---------------------------------------------------------------------------------- |
| `OK`         | 全計算時刻で位置・任意の姿勢誤差が許容内、全リンクが領域内、全補間区間を安全と確認 |
| `NG`         | IK未収束、または時刻・補間区間に領域逸脱がある                                     |
| `UNVERIFIED` | 計算時刻は通過したが、補間区間の安全性を確認できない                               |

位置・姿勢の軌道追従誤差は**指定した計算時刻**での評価です。高周波・不連続な関数では刻みを細かくしてください。フレーム間の領域包含は別途保守的に検証します。`minClearance` は実際に検査した姿勢での最小値で、全連続時刻における厳密な最小距離ではありません。

ソルバーは有限差分ヤコビアン、減衰最小二乗、領域違反ペナルティ、関節角制限、複数初期値探索を使用します。前時刻の解を次時刻に引き継ぎます。未収束は解の不存在の証明ではありません。初期角度、反復数、探索数、軌道、寸法を変更して再計算できます。参考: [Samuel R. Buss — Inverse Kinematics](https://mathweb.ucsd.edu/~sbuss/ResearchWeb/ikmethods/)。

## エージェント・CLIによるシミュレーション

描画もブラウザーも不要で、画面と同じエンジンを実行できます。

```sh
# 標準ケース
npm run simulate

# 保存した設定を再現
npm run simulate -- examples/orbit.json output/orbit

# 球の領域、姿勢を含む軌道
npm run simulate -- examples/sphere.json output/sphere
npm run simulate -- examples/fixed-orientation.json output/pose

# 意図的な失敗ケース（終了コード2が正常な期待結果）
npm run simulate -- examples/outside-workspace.json output/outside
npm run simulate -- examples/unreachable.json output/unreachable
```

出力先に `config.json`, `result.json`, `trajectory.csv` を生成します。標準出力は状態・収束数・最大誤差・領域余裕・最初の問題時刻のJSON。終了コード **0=OK、2=NG/UNVERIFIED、1=設定・実行エラー**です。出力は `output/` に保存しGitには含めません。

エージェントは設定JSONをコピーして関数・初期角度・寸法・領域を調整 → CLI実行 → `result.json` の未収束時刻・違反リンク・補間検査を分析 → 再実行できます。同じ入力は同じ解を再現します（実行時間を除く）。意図した制約を満たすために、許容誤差や領域を無断で緩める必要はありません。

主なファイル:

| ファイル                   | 責務                              |
| -------------------------- | --------------------------------- |
| `src/core/config.ts`       | 初期値・設定検証                  |
| `src/core/expression.ts`   | 安全な数式パーサー                |
| `src/core/kinematics.ts`   | FK、全リンク包含、制約付き数値IK  |
| `src/core/simulation.ts`   | 軌道計算、補間検査、再生補間、CSV |
| `src/simulation.worker.ts` | ブラウザーの非同期計算            |
| `src/Scene.tsx`            | Three.jsの描画                    |
| `scripts/simulate.ts`      | CLI実行                           |

## 検証

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Chromeがインストール済みで、Chromiumを追加ダウンロードせず使う場合（PowerShell）:

```powershell
$env:PLAYWRIGHT_CHANNEL = 'chrome'
npm run test:e2e
```

数値テストはFKの既知姿勢、180度の姿勢誤差、太さ込み包含、球、既知の6D姿勢のIK、到達不能、フレーム間逸脱、不確定区間、式の拒否、再現性を確認します。PlaywrightはPC・スマートフォンの2サイズで、WebGL・再生・スクラブ・編集・NG表示・JSON往復・CSV出力を確認します。

対象は運動学です。自己衝突・外部障害物・力学・トルク・荷重・関節速度/加速度・特定実機の較正は未実装です。表示モデルと指定した許容領域の範囲で判定します。
